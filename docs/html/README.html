Brain control of bimanual movement enabled by recurrent neural networks

Overview

This repo is associated with this paper and dataset. The code contains a simple Matlab analysis script that demonstrates how to load the datasets and plot cosine tuning curves relating brain activity to directional unimanual/bimanual hand movement.

To execute the analysis script (tuningAnalysis.m), change the dataPath variable to point at the data directory and hit 'run'.

Replication (fork)

This branch (replication) adds an independent Python replication of the paper's offline analyses, plus four extensions that go beyond the paper. Everything runs from the public Dryad data. The online experiments can't be re-run, so Fig 5 is re-scored from the logged closed-loop trials.

Start here: docs/report.md is a short narrative of all findings.

How this was built: most of the code was written with an AI coding assistant. WORKING_WITH_AI.md explains how the science was kept checkable, with tips for presenting work like this.

Findings in brief

  • The replication holds. Every qualitative claim of the paper replicates, and most headline numbers fall within a few points:
    • The left hand's tuning is suppressed about 2× more than the right hand's during bimanual movement, and laterality dominates the neural variance.
    • Nonlinear decoders win because they use the laterality signal.
    • Time-warp augmentation costs a little offline accuracy.
  • Remaining differences are small:
    • The paper's text calls bimanual time to target "only slightly longer". The logs show about 2× unimanual, and so does the paper's own Fig 5a.
    • We find fewer single-electrode-tuned channels than Supp Fig 1.
    • See docs/figure_comparison.md.
  • Extensions:
    1. LSTM vs GRU (Phase 8): the LSTM ties the GRU on raw data and loses less under augmentation.
    2. One array (Phase 9): on day 1869, array B alone (channels 97–192) keeps 98–103% of the two-array performance.
    3. Feasibility for a smaller implant (Phase 10): 8 well-chosen channels of one array keep 86–97% of the performance. Training with channel dropout makes the decoder robust to detected channel loss. Undetected dead channels break every decoder. One 4-min block of training data gives about 95%.
    4. Threshold crossings vs spike-band power (Phase 11; public T5 data, 48 electrodes): SBP is 4–9% behind with all electrodes and equal or ahead with 4–16. See the caveats in docs/ext_sbp_notes.md.

Viewing the replays

  • Open it in any browser. docs/html/replays.html is self-contained (about 10 MB, data embedded), so it needs no server and no Python. Only the fonts come from the internet; offline it uses system fonts.

  • Online copy: the same replays are published at https://claude.ai/artifact/8uo59AGFwhUPsZWmH16KA4 (a Claude artifact). It is private to its owner's claude.ai account until they share it from there, so anyone else gets an access page rather than the replays. It can also lag behind the copy in git, which is the reference version.

  • From GitHub, an HTML file shows as source code. Either download it (open the file, then Download raw file), or serve it with GitHub Pages: Settings → Pages → Deploy from a branch, branch replication, folder /docs. The page is then at https://<user>.github.io/bimanualBCI/html/replays.html. Pages makes that folder public, and private repositories need a paid plan for it.

  • Rebuilding (pixi run replays) needs inputs that are not in git, about 220 MB in total:

    • the Dryad files for days 1778, 1855, 1869, 1881 and 1883 in Data/;
    • 11 model checkpoints in results/checkpoints/;
    • three Fig 3 caches in results/cache/.

    Keep a backup of these if you may want to change the replays. Without them, the caches come back with pixi run fig3-decoding --force, but the checkpoints need retraining (fig4-rnn, ext-lstm, ext-arrays, ext-feas: several GPU-hours). The script refuses any model that doesn't reproduce its logged test r.

Setup

  1. Install pixi, then run pixi install.
  2. Download the Dryad data and extract the .mat files and readme.txt into Data/.
  3. Phase 11 only: download fig1_T5_delay.h5 and fig1_T5_move.h5 from Rigotti-Thompson et al. 2026 into Data/ext/.

The GPU steps were run on an RTX 3050 laptop GPU (4 GB). The times below refer to it.
